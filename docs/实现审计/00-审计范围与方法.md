## 审计方法

1. 结构扫描: 使用 `rg --files`、`git ls-files`、`find` 建立项目目录、文件类型、模块边界。
2. 关键链路阅读: 定位脚本执行、外部入口、权限、截图、OCR、插件、构建发布的入口文件并读取上下文。
3. 静态风险搜索: 扫描 `catch/Throwable/printStackTrace`、动态加载、`addJavascriptInterface`、Root/shell、MediaProjection、native lock/unlock、远程 URL、签名/密码等模式。
4. 并行分区审计: 使用子代理分别审计运行时/Core/native/构建供应链四个独立面, 主线程复核并去重。
5. 文档归档: 将问题按系统分册落地, 另建全量覆盖清单作为文件级确认证据。

## 严重程度定义

| 严重程度 | 定义 |
| --- | --- |
| `CRITICAL` | 可导致任意脚本执行、高权限越权、签名密钥暴露或同等级安全事故 |
| `HIGH` | 明确崩溃、竞态、资源泄漏、供应链污染或高权限能力失控风险 |
| `MEDIUM` | 影响稳定性、兼容性、可维护性、诊断能力或在特定条件下扩大风险 |
| `LOW` | 技术债、兼容性隐患、日志/体验/长期演进问题 |

## 优先级定义

| 优先级 | 定义 |
| --- | --- |
| `P0` | 应立即处理; 不处理会影响安全边界、发布安全或核心能力稳定性 |
| `P1` | 近期主线修复; 风险明确且修复收益高 |
| `P2` | 中期修复; 需要结合重构/测试/策略一起落地 |
| `P3` | 长期治理; 可作为专项或技术债排期 |

## 文件级确认口径

- 源码文件: 通过分区阅读、模式扫描、关键链路复核确认。
- 构建/配置文件: 通过依赖解析、远程下载、CI、签名、版本写回路径确认。
- 资源文件: 通过 Manifest、资源目录、运行时消费链路和覆盖清单确认。
- 二进制文件: 通过清单、构建引用、版本/来源、调用链和供应链风险确认; 未对所有 AAR/JAR/SO 做反编译和符号级审计, 已在对应分册标为后续专项。
