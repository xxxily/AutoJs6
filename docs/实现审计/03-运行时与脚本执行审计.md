- `app/src/main/java/org/autojs/autojs/external/**`
- `app/src/main/java/org/autojs/autojs/engine/**`
- `app/src/main/java/org/autojs/autojs/runtime/**`
- `app/src/main/java/org/autojs/autojs/script/**`
- `app/src/main/java/org/autojs/autojs/timing/**`
- `app/src/main/java/org/autojs/autojs/core/web/**`
- `app/src/main/java/org/autojs/autojs/core/ui/widget/EventWebView.kt`

## 已确认未发现明确实现级问题的关键文件

以下文件在本轮运行时链路审计中未发现可直接定性的实现问题, 保持作为覆盖确认记录:

- `app/src/main/java/org/autojs/autojs/runtime/ScriptRuntime.kt`: `onExit()` 已集中回收 console、events、threads、timers、images、automator 等多数运行时资源; 问题集中在被调用对象自身回收不完整。
- `app/src/main/java/org/autojs/autojs/execution/LoopedBasedJavaScriptExecution.java`: loop-based 执行链路整体具备结束回调和中断处理; 风险已归并到 engine 注册竞态和 timer 回收。
- `app/src/main/java/org/autojs/autojs/timing/TimedTaskScheduler.kt`: alarm pending intent 已按不可变口径处理, 本轮未发现明显 pending intent mutable 风险。
- `app/src/main/java/org/autojs/autojs/script/JavaScriptSource.kt` 与 `JavaScriptFileSource.java`: source 抽象结构清晰; 文件流关闭问题已在 RT-08 记录。
- `app/src/main/java/org/autojs/autojs/runtime/api/augment/engines/Engines.kt`: 主要问题来自底层 manager/service 生命周期, 脚本侧包装未发现额外高风险入口。

## 后续验证建议

- 为 `RunIntentActivity`、`FireSettingReceiver`、动态 receiver 增加外部应用触发的 instrumentation 负例测试。
- 为 `ProcessShell` 增加脚本停止时子进程销毁测试, 覆盖 sleep/长时间命令/Root 命令。
- 为 `EventEmitter.once`、`Timers.recycle()`、`TimedTaskManager` action 更新增加 JVM 单元测试。
- 对所有 `addJavascriptInterface` 调用建立统一审计清单, 明确每个 bridge 的 origin、能力和默认启用条件。
