# 底层实现地图

## 工程结构

AutoJs6 是 Android/Kotlin/Java 多模块工程, 根工程包含:

- `app`: 主应用、脚本运行时、UI、自动化能力、截图/OCR/OpenCV、插件中心、APK 构建入口。
- `modules`: vendored/改造后的 Java/Kotlin 库, 包含 `apk-parser`、`apk-signer`、`jieba-analysis`、UI 组件库等。
- `libs`: 本地 AAR/JAR/native 库包装, 包含 OpenCV、RapidOCR、imagequant、terminal/root-shell 等。
- `plugin-api`: Paddle OCR 插件 API 与内嵌引擎实现。
- `build-logic`: Gradle convention、远程 native 包下载/部署、版本代码 KSP 处理器。
- `gradle`: wrapper、version catalog、AGP/Kotlin/KSP/Java 兼容数据。
- `docs`: 当前需求/发布规范与本次实现审计文档。

## 脚本执行链路

核心链路:

1. 外部入口或 UI 创建 `ScriptSource`。
2. `Scripts.run()` 或 `ScriptIntents.handleIntent()` 调用 `AutoJs.instance.scriptEngineService.execute(...)`。
3. `ScriptEngineService` 创建 `ScriptExecution` 与脚本线程。
4. `ScriptEngineManager` 管理 engine 实例。
5. `RhinoJavaScriptEngine` 进入 Rhino context, 注入 `ScriptRuntime`。
6. `ScriptRuntime` 暴露 `files/images/automator/shell/shizuku/plugins/ui/timers/events` 等 API。
7. 脚本结束时由 `ScriptRuntime.onExit()` 回收 runtime 资源。

主要问题集中在外部入口信任边界、engine 注册/启动竞态、shell 中断语义、timer/event 回收和 reader/stream 关闭。

## 自动化与权限能力

底层自动化能力集中在:

- `core/accessibility`: Accessibility service、simple automator、截图、delegate。
- `core/automator`: UI 对象、selector、action、BFS/DFS 搜索。
- `core/inputevent`: RootAutomator、input device 解析、getevent 观察。
- `runtime/api/augment/automator`: 脚本侧自动化 API 包装。

这些能力依赖 Manifest 中的宽权限声明、用户授权、Root/Shizuku 或 Accessibility service。主要风险是导出入口绕过用户确认后触发高权限脚本能力, 以及 Accessibility/native buffer/root input 的资源和异常处理。

## 截图、图像与 OCR

截图链路:

- `ScreenCaptureRequester` 负责 MediaProjection 授权与前台服务时序。
- `ScreenCapturer` 管理 `MediaProjection`、`VirtualDisplay`、`ImageReader`。
- `Images` 将 `Image` 包装成 `ImageWrapper`, 提供截图、保存、OpenCV 操作。

OCR 链路:

- `runtime/api/augment/ocr` 选择 MLKit/Rapid/Paddle。
- `libs/rapidocr` 提供 RapidOCR native 实现。
- `plugin-api/paddle-ocr-engine` 提供 Paddle OCR native bridge。
- `core/plugin/ocr` 提供 OCR 插件 host 连接和授权。

主要问题集中在 native 初始化失败处理、并发 detect/release、Bitmap/HardwareBuffer 资源关闭、模型 assets 复制和二进制依赖陈旧性。

## WebView 与 UI bridge

WebView 相关实现包括:

- `core/ui/widget/EventWebView.kt`: 自定义事件 WebView, 注入 `$autojs` JavaScript bridge。
- `core/web/InjectableWebClient.java` / `InjectableWebView.kt`: 注入 `rhino` bridge, 可从 WebView JS 侧执行 Rhino 代码。
- UI inflater/attribute 系统: 将脚本 XML/UI 绑定到 Android view。

主要风险是 `addJavascriptInterface`、`allowUniversalAccessFromFileURLs`、file URL 和 Rhino eval bridge 同时存在时形成高风险执行面。

## 插件体系

插件中心链路:

- `PluginIndexRepository`: 拉取官方插件索引。
- `PluginInstaller`: 下载/安装 APK。
- `PluginTrustManager` / `PluginAuthorizationStore`: 基于签名指纹和用户授权做运行门禁。
- `PaddleOcrPluginHost`: OCR 插件连接池和授权。

当前运行时门禁存在, 但索引本身未做签名、手输 URL 安装缺 hash/HTTPS 约束、脚本退出后的插件服务解绑需要补齐。

## 构建与发布链路

构建发布链路包括:

- `settings.gradle.kts`: 动态选择 AGP/Kotlin/KSP/Java 版本。
- `build.gradle.kts`: 全项目仓库配置。
- `build-logic/convention`: 版本、签名、native 包下载部署、压缩包解压。
- `.github/workflows/android.yml`: CI 构建发布。
- `app/build.gradle.kts`: APK 产物、签名、lint、digest 等。

主要问题是远程下载缺少可信 checksum、压缩包解压缺 Zip Slip 防护、CI 执行远程 installer、wrapper 缺 SHA-256、release 构建签名校验不够强。
