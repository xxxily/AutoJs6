# 定时任务可靠性与运行记录

> 任务: T54 / A8
> 日期: 2026-06-09

## 实现范围

- 新增 `TimedTaskRunRecord` 运行记录模型和 `TimedTaskRunRecordDatabase` 独立数据库.
- 定时任务触发统一走 `TimedTaskManager.triggerTask(...)`, Alarm、Work、Job、补偿执行都记录后端和触发原因.
- `ScriptIntents.handleIntent(...)` 支持注入 `ScriptExecutionListener`, 用真实脚本开始、成功、异常事件更新记录.
- `TimedTask` 持久化可靠性策略字段: `maxRetries`, `retryBackoffMillis`, `mutex`, `mutexKey`, `timeoutMillis`.
- `tasks` 新增 `queryTimedTaskRuns(options)` 和 `queryTimedTaskQueue()`.

## 运行记录字段

记录包含 `taskId`, `executionId`, `scriptPath`, `eventType`, `scheduledAt`, `triggeredAt`, `startedAt`, `finishedAt`, `launchStatus`, `finishStatus`, `exception`, `duration`, `backend`, `deviceState`, `degradationReason`, `nextScheduledAt`, `retryAttempt`, `maxRetries`, `backoffMillis`, `mutexKey`, `timeoutMillis`.

`eventType` 当前包括:

- `run`: 正常触发.
- `retry_run`: 失败/超时后的重试触发.
- `compensated_run`: 检查任务时发现计划时间已过, 立即补偿执行.
- `schedule_degraded`: 精确 Alarm 调度失败并降级到 WorkManager.

## 可靠性策略

- `maxRetries`: 单次计划执行的最大重试次数, 归一化范围为 `0..10`.
- `retryBackoffMillis` / `retryBackoff`: 首次重试退避时间, 后续指数退避, 上限 1 小时.
- `mutex`: 为真时按脚本路径互斥.
- `mutexKey`: 自定义互斥 key, 优先级高于脚本路径.
- `timeoutMillis` / `timeout`: 单次脚本执行超时时间, 超时后记录 `finishStatus=timeout` 并尝试停止脚本引擎.

## 脚本 API

```js
var runs = tasks.queryTimedTaskRuns({ taskId: 1, limit: 20 });
var queue = tasks.queryTimedTaskQueue();
```

`queryTimedTaskRuns` 默认返回最近 50 条, `limit` 限制为 `1..500`. `queryTimedTaskQueue` 返回当前已登记定时任务的下一次计划时间、后端、是否已调度和可靠性策略字段.

## 验收要点

- AlarmManager `setExactAndAllowWhileIdle` 抛异常时会写入 `schedule_degraded` 记录, 并把调度交给 WorkManager.
- 失败、异常、超时记录可查询 `exception`, `duration`, `backend`, `nextScheduledAt`.
- 重试、补偿、互斥、超时均由 `TimedTaskManager` 统一处理, 避免不同后端行为分叉.
- JVM 测试覆盖 `TimedTaskReliabilityPolicy` 和 `TimedTaskRunRecord` 状态转换.
