## 关键结论

当前项目的底层能力非常宽: 脚本运行时、无障碍自动化、截图/OCR/OpenCV、Root/Shizuku/input、插件中心、APK 构建和多模块 Gradle 构建都已经成型。主要风险不是单点 API 缺失, 而是高权限执行入口、native 资源生命周期、外部供应链校验、脚本/服务生命周期竞态和二进制依赖可追溯性。

最优先处理的 P0/P1 问题集中在:

- 外部导出的脚本执行入口可被任意应用触发。
- WebView/Rhino bridge 与 file URL universal access 组合形成高风险执行面。
- 本地 `sign.properties` 存在明文签名口令。
- RapidOCR/Paddle OCR native 初始化与释放存在崩溃或竞态风险。
- 远程构建依赖下载、CI installer、压缩包解压和 Gradle wrapper 缺少完整性约束。
